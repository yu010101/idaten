# Chrome と Idaten のメモリ比較(2026-09-23)

## 測った条件(揃えたもの)
- 同じ12ページ(`tools/bench/urls.txt`)を、同じ順序で、コマンドライン引数として両ブラウザに渡す
- どちらも**新品のプロファイル**(拡張なし・ログインなし)で起動。起動は `open -g -n -a`
  (端末から直接起動すると WebKit の子プロセスの responsible pid が端末になり、取りこぼす)
- 読み込み待ち45秒 → 測定 → 放置60秒 → 測定。**3回**繰り返し
- 測る値は `ri_phys_footprint`(圧縮・スワップ込み。Activity Monitor の「メモリ」と同じ会計)。単位は MiB
- 機械: MacBook Pro M1 Pro / 16GB / macOS 26.5

## 結果(3回。中央値)

| | プロセス数 | 読み込み直後 | 60秒放置後 |
|---|---|---|---|
| Chrome | 74 → 104 | 4,131 MiB | 6,250 MiB |
| Idaten | 11 | 858 MiB | 881 MiB |

生の値:

| 回 | Chrome 読込 | Chrome 放置 | Idaten 読込 | Idaten 放置 |
|---|---|---|---|---|
| 1 | 74 / 4,131.5 | 100 / 5,771.2 | 11 / 857.5 | 11 / 880.8 |
| 2 | 69 / 4,107.9 | 109 / 6,249.5 | 11 / 821.9 | 15 / 643.0 |
| 3 | 76 / 4,672.3 | 104 / 6,295.6 | 11 / 951.4 | 11 / 981.5 |

放置後の比は約 **7.1 倍**(6,250 ÷ 881)。プロセス数は約 9 倍。
Chrome は放置中にプロセスもメモリも**増えた**(広告・計測スクリプトが動き続けるため、と推測)。

## この数字で言えること・言えないこと
**言える**: この12ページ・この手順・この機械で、Idaten の方がメモリもプロセス数も大幅に少なかった。3回とも同じ向き。

**言えない**(条件が揃っていない・未検証):
1. Chrome の省メモリ機能(Memory Saver)は数時間単位で効くので、60秒の放置では働いていない。
   長時間の比較は未実施。
2. Idaten 側の WebKit は**本人のプロファイルのデータストア**を使っている(Cookie・キャッシュが温かい)。
   Chrome 側は新品。キャッシュ条件が同じではない。
3. 動画タブを含んでいない(URL一覧に動画が無い)。動画は両者で優劣が入れ替わった記録がある。
4. 瞬間値を2点取っただけで、区間の中央値・ピークを取っていない。反復も3回(公開主張には10組以上が要る)。
5. 測定中、本人の Chrome が動いていた(別プロセス群なので合算はしていないが、機械全体の負荷は共有)。
6. メモリ以外の対価(再訪時の読み直し・CPU・通信量)を測っていない。

## 次に詰めること(Codex の指摘より)
- 動画1本を含む13タブの固定シナリオ、20/60/200タブ版
- 60秒 / 5分 / 15分の共通観測点、区間の中央値とピーク
- Chrome の Memory Saver を明示設定した条件、Chrome + 同じ休眠拡張の条件、Helium 単体の条件
- 条件ごとに10組、AB/BA を均等に
